# 自官方 v1.4.2 以来的改动

分支 `lightweight-workflows` 从官方 Plane `release: v1.4.2`（`5f7d92784`）切出，当前版本是 `1.5.0`。下面记的是这条分支上已经落地、并且和官方行为不同的功能。从官方 1.4.2 数据库迁过来的步骤见 [从官方1.4.2迁移.md](./从官方1.4.2迁移.md)。更细的实现约定仍写在各功能自己的文档里。

已有项目、已有用户资料、已导入的状态名，都不会被迁移脚本改写。下面说的“新建项目”“新用户”只作用于之后创建的数据。

## 轻量工作流

项目可以单独启用一套固定的业务流转。启用前，任务状态仍按 Plane 原来的方式随便改。关掉之后，配置还留着，但状态选择立刻恢复成官方那种不限制目标状态的编辑。

业务角色和 Plane 的 Admin、Member、Guest 分开。一个成员可以同时是项目经理，也仍然只是 Member。角色有四种：产品、开发、测试、项目经理。

启用工作流后，状态选择器只显示当前状态，以及当前这个人允许选的目标状态。鼠标悬停或键盘聚焦时会预先拉取可选状态；请求还没回来时，菜单保持打开并显示加载，避免连点被当成立刻关闭。

项目经理可以把自己负责的任务从当前状态改到任意已配置的业务状态。普通角色只能走下面这些边。

主流程：

- 产品：`需求完善 → 待做`；`测试中 → 完成`；从 `开发中`、`开发完成` 或 `测试中` 改为 `取消`。
- 开发：`待做 → 开发中`；`测试打回 → 开发中`；`开发中 → 开发完成`。
- 测试：`开发完成 → 测试中`；`测试中 → 测试打回`。
- 项目经理：`测试中 → 延期完成`。

带标签 `类型/缺陷` 的任务走缺陷流程，主任务和子任务都算。缺陷从 `测试打回` 回到 `开发中` 由开发操作。到了 `开发中` 之后，测试可以改为 `完成`，产品可以改为 `取消`，项目经理可以改为 `挂起` 或 `延期完成`。

`延期中` 在状态目录里，但普通角色没有指向它的边，只有项目经理能选。`挂起` 对普通角色没有出去的边，项目经理仍可以把它改走。

带标签 `阻断`、且还不是 `完成`、`延期完成` 或 `取消` 的直接子任务，会拦住主任务进入完成类状态。这是原有拦截，连带完成子任务也不会绕过它。

谁做了最近一次被接受的状态变更，谁可以把这一步撤回到紧挨着的上一个状态。任务如果已经被别人再改过，这次撤回就不出现。撤回会当场记下来，不等后台活动任务。

每次被接受的状态变更，除了 Plane 原来的 `issue` webhook，还会多发 `issue.workflow_transition`。内容包括语义状态、具体状态记录、主流程或缺陷流程、所需角色、操作人、schema 版本，以及是不是撤回。被拒绝的变更不发这条事件。

配置、角色和流转记录放在新增表里。初始化时如果项目里已经有同名状态或标签，就沿用，只补缺的，不改名、不删除。旧英文名 `Backlog`、`Todo`、`In Progress`、`Done`、`Cancelled`，以及 `等待测试`、`等待测试/开发完成`，在初始化时仍能对上，并保持原名。

设计说明见 [lightweight-workflow.md](./lightweight-workflow.md)。

## 新建项目的默认状态

新建项目不再使用官方的 Backlog、Todo、In Progress、Done、Cancelled。默认状态按下面的顺序创建，Triage 仍是隐藏状态，只给 Intake 用：

| 状态             | Plane 分组 | 颜色      |
| ---------------- | ---------- | --------- |
| 需求完善（默认） | Backlog    | `#60646C` |
| 待做             | Unstarted  | `#60646C` |
| 开发中           | Started    | `#F59E0B` |
| 开发完成         | Started    | `#8B5CF6` |
| 测试中           | Started    | `#3B82F6` |
| 测试打回         | Started    | `#EF4444` |
| 完成             | Completed  | `#46A758` |
| 延期完成         | Completed  | `#0E7490` |
| 取消             | Cancelled  | `#9AA4BC` |
| 延期中           | Cancelled  | `#D97706` |
| 挂起             | Cancelled  | `#78716C` |
| Triage           | Triage     | `#4E5355` |

`开发完成` 是唯一名称。以前文档和配置里的 `等待测试`、`等待测试/开发完成` 只用于认出旧数据，不会再新建一个同义状态。

`完成` 用绿色，`延期完成` 用青色，避免两个完成态靠色太近。`延期中` 和 `挂起` 排在 `取消` 后面，分组是 Cancelled，但工作流里它们仍是独立状态，不能当成 `取消` 来跳转或跳过子树。

因为进了 Cancelled 分组，Plane 会把 `延期中` 和 `挂起` 的任务算进已关闭数量，图标也用取消分组的形状，并且可以按取消类任务归档。这是分组带来的副作用，不是把它们合并成 `取消`。

启用工作流仍是另一步。只新建项目、不启用工作流时，这些状态可以自由切换。

## 项目经理连带完成子任务

只在已启用轻量工作流的项目里生效。项目经理把任务改成 `完成` 或 `延期完成`，并且阻断子任务的拦截已经通过时，如果同一项目的子树里还有可以改的任务，就弹出确认。没有可改的子任务时不弹窗，父任务照常完成。

选“是”：父任务进入刚才选的 `完成` 或 `延期完成`；符合条件的整棵子树改为 `完成`，不会跟着父任务变成 `延期完成`。选“否”或关掉弹窗：只完成父任务，子任务不动。

子树按父子关系往下走，不走关联任务，也不跨项目。下面这些节点自己不改，它下面的分支也不再往下走：

- `取消`
- `延期中`
- `延期完成`
- `挂起`
- 带 `阻断` 标签的任务

已经是 `完成` 的节点不改，但它下面没有被上面这些规则截断的任务，仍会改为 `完成`。某个子任务自己还有未结束的阻断子任务时，这一条留下并在结果里报出来；已经改成功的兄弟任务不回滚。产品、开发、测试看不到这个弹窗。

在工作项侧栏里点“是”或“否”时，侧栏保持打开，任务行和子工作项区域原来的展开、收起状态也不变。单独打开的任务详情页本来就没有这个问题。

## 周期统计

周期任务列表本来就不显示 Triage 状态的任务。以前总数仍把它们算进去，所以全部可见任务都完成后，进度仍到不了 100%，转移数量里也会剩下一笔实际转不走的任务。

现在周期的总数、估算点数、负责人分布、标签分布和燃尽图都不计入 Triage。进度用完成数除以“总数减去取消数”。已经结束并保存过进度快照的周期，读取时把总数改成待办、未开始、进行中、完成、取消这几组合计，快照里多出来的 Triage 不再进分母。

Triage 任务还可以留在周期关联里，只是不参与这些数字。以嵌入式周期为例，隐藏的 Triage 任务不再把 15 个已完成任务显示成 15/16。

## Intake

每个项目的 Intake 可以保存最多 20 个 Markdown 模板，并可指定一个默认模板。入口在“项目设置 → 功能 → Intake”。创建时把模板内容填进描述，标题和 Plane 的其他属性仍由提交人填写，也可以不用模板。模板不包含状态；新收集的工作项仍进入 Triage。项目管理员维护模板，成员和访客只能读取和使用。旧 Intake 的模板字段是空对象。见 [intake-templates.md](./intake-templates.md)。

接受收集项时，管理员可以选同一工作区里自己有创建权限的其他项目。选当前项目时行为和官方一样。选别的项目时，工作项 UUID 不变，编号换成目标项目的编号，状态换成目标项目默认的非 Triage 状态。Intake 记录仍留在来源项目。标签、周期、模块、父子关系、工作项类型、估算、工作流撤回记录和 GitHub 同步会清掉；负责人只保留目标项目的活跃成员；评论、附件、链接、反应和版本历史跟着同一个 UUID 过去。不传目标项目时，仍接受到来源项目。见 [intake-cross-project-acceptance.md](./intake-cross-project-acceptance.md)。

已拒绝的收集项不再是终点。项目管理员可以之后再接受它，也可以接受到另一个项目。它留在已处理列表里，状态从已拒绝变成已接受。已接受和重复项不能再改状态。

## 跨项目关联

关联仍用 Plane 原来的工作项关联，以及“当前项目 / 整个工作区”搜索。工作区搜索的范围仍是当前用户作为活跃成员的项目。多条业务任务可以关联同一个测试单。

来源任务上会显示对方的项目标识和当前状态，用来看完成情况。这一行不能改对方的状态、优先级、负责人，也不能删除对方任务；取消关联本身还可以。打开或修改对方任务，仍按对方项目的成员权限。关联不会自动关任务，也不会变成工作流门槛。见 [cross-project-relations.md](./cross-project-relations.md)。

## Webhook 投递

投递失败不再把管理员打开的 webhook 自动关掉。网络错误以及 HTTP `408`、`425`、`429`、`5xx` 会按指数退避重试：大约 1 分钟后开始，两次之间最长 1 小时，单条事件最多 12 次，并带抖动。12 次用完后，这一条记为失败，订阅仍是启用的；下一次匹配的事件会重新投递。其他 `4xx` 视为请求本身有问题，只记日志，不重试。SSRF 校验失败仍按原来的方式拒绝并记日志，也不停用订阅。见 [webhook-delivery-retries.md](./webhook-delivery-retries.md)。

## 本地运行和界面

`plane.settings.workflow_local` 用于没有 Docker、Redis、RabbitMQ、S3 的单机验证。Redis、消息队列和对象存储换成进程内或本地文件；Celery 任务当场执行；关掉 Django debug toolbar，减少每条请求的控制台日志，并复用数据库连接。要用 ASGI（例如 Uvicorn），不要用 Django 自带的开发服务器。这套配置不能用于生产或多进程部署。

本地上传走原来的 V2 资源流程，但预签名表单换成短期签名的 API 上传。签名绑定资源 ID 和服务端生成的存储键。只有显式打开本地文件存储时，匿名上传端点才可用。文件仍受 Plane 的大小限制。头像、标志和项目封面从本地文件提供，并带 `nosniff`。生产和容器部署仍走 S3 或 MinIO。见 [local-asset-storage.md](./local-asset-storage.md)。

登录和跨域信任 `http://127.0.0.1:3000`、`http://localhost:3000`，以及 `APP_BASE_URL` 配的来源。要用局域网地址访问时，把 `APP_BASE_URL` 设成那台机器的地址，并把 ASGI 绑到对应网卡。浏览器、API 和 `APP_BASE_URL` 的主机名要一致，否则 CSRF 会失败。

没有明确语言偏好时，界面默认简体中文。未登录页、首次渲染、退出登录后的重置，以及新的 `Profile.language`，都是 `zh-CN`。已经选过语言的用户不会被改掉。见 [default-language.md](./default-language.md)。

工作区通知收件箱标题前有返回箭头，直接回到当前工作区首页 `/${workspaceSlug}/`。见 [notification-inbox-back-navigation.md](./notification-inbox-back-navigation.md)。

## 工作项历史

任务历史接口在把活动记录和评论混在一起排序之前，没有先序列化。合并后的列表不是可返回的 JSON，按 `created_at` 排序也会失败。现在两边都先序列化，再按时间排成一份历史。只查评论的分支本来就是序列化后返回，没有改。
